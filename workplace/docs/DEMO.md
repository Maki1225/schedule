# デモの使い方

Study Plannerのデモでは、4人のデモプロフィールを切り替えながら、カレンダー・課題・グループ・チャットを試せます。

## デモを始める

1. Study Plannerのトップページで「デモモード」を開きます。プロフィール選択欄にはクラス全体の相関図も表示されます。
2. ゆいと、あおい、はるひ、なみのいずれかを選びます。
3. カレンダー・課題、グループ・チャット、クラス相関図を画面上部のナビゲーションから切り替えます。

デモ中にクラス相関図を開くと、ログイン中のプロフィールが中央に表示され、他のメンバーとのつながりを確認できます。線上のラベルで、同級生・実験班への所属・グループワークでの協力関係を見分けられます。人物カードを選ぶと詳細が表示され、画面下のプロフィールカードも確認できます。プロフィールカードから別のデモユーザーへ切り替えることもできます。

## デモで試せること

- カレンダーで予定・課題を確認し、課題や予定を追加・編集する
- グループを作成する、招待コードを使って参加する、グループから退出する
- グループ内でメッセージを送受信する
- 課題を追加したとき、グループチャットへ自動通知されることを確認する
- クラス相関図とプロフィールを確認する

招待コードで参加できるのは、デモ用プロフィールが所属しているグループです。デモ中に作成・参加・退出したグループや、追加した課題・予定・メッセージは、本番データには保存されません。

## デモデータの保存期間

デモ中の変更はブラウザーの `sessionStorage` に保存されます。同じタブでデモ画面間を移動している間は保持されますが、ページを再読み込みする、デモを終了する、またはデモ画面の外へ移動すると消去されます。デモチャットは1セッションにつき10通まで送信でき、不適切な表現を含むメッセージは送信できません。

デモ開始時のプロフィール、グループ、既存の予定などの読み込みには、設定済みのバックエンドを使用します。相関図とプロフィールに表示される登録課題数も、バックエンドDBに登録済みの課題数です。デモ中にセッション内で追加した課題はこの数に反映されません。デモ中に新しく加えたデータのみ、セッション内の一時データとして扱われます。

## ローカルで表示する

リポジトリのルートで静的サーバーを起動します。

```bash
python3 -m http.server 8765 --directory workplace/frontend
```

ブラウザーで <http://127.0.0.1:8765/index.html> を開き、上記の手順でデモを開始してください。ローカル環境からデモを利用するには、設定済みバックエンドが稼働しており、`http://127.0.0.1:8765` からのアクセスをCORSで許可している必要があります。CORSエラーが出る場合は、バックエンドの許可Origin設定とデプロイ状況を確認してください。

## バックエンド・DBの準備

デモ開始時にはバックエンドがデモセッションを発行します。デモ用アカウントと既存グループ・予定の読み込みには、バックエンドとDBの設定が必要です。ローカルでバックエンドを起動する場合の環境変数と手順は、[開発者ガイド](./DEVELOPMENT.md)を参照してください。

通常モードのグループチャットと課題の自動通知を使う場合は、Neon PostgreSQLに [`20261101_create_group_chat_messages.sql`](../backend/migrations/20261101_create_group_chat_messages.sql) を適用してください。課題の作成者・最終編集者と編集時刻の表示に必要なDB列は、[`20261101_add_event_audit_metadata.sql`](../backend/migrations/20261101_add_event_audit_metadata.sql) で追加します。マイグレーションの適用方法はDB管理者に確認してください。
